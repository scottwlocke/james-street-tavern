{{- /* Responsive image derivatives for a dish photograph, as a dict for the caller to place. Why this exists: the 46 dish photos are 1600×1000 PNG at ~208 KB, but the largest slot they ever fill is .detail-media at ~440px wide (§7 — 5fr of a 1200px container), and a card fills ~357px. So the 1600px original was being served into a 440px box: about 3.6× oversized. Measuring the same photo through Hugo Pipes: 1600px PNG (the source) 206 KB 1080px WebP 14 KB 768px WebP 9 KB 480px WebP 5 KB 1080px JPEG 33 KB So this returns a WebP srcset for the browsers that will take it, and a single JPEG as the fallback. Widths stop at 1080 rather than reaching the 1600px source: nothing on the site has a slot wider than 440px, so 1080 already covers a 440px box at ~2.5× density, and carrying a fourth variant up to the source size would re-add the bytes this exists to remove. The photo lives in its own page bundle, beside the index.md it belongs to, so a page can only ever resolve its own file through $page.Resources.GetMatch. Bundle resources publish verbatim whether or not a template uses them, so every menu section's _index.md carries a `build.publishResources = false` cascade: the untouched 1600px PNG stays out of public/ and only the fingerprinted derivatives below reach the wire. (The specials section sets the same cascade for the same reason.) Returned as a dict rather than printed markup, because the two call sites need different `sizes` and different `loading`/`fetchpriority`: a card is lazy-loaded and decorative, the detail image is the LCP element and carries the dish name as its alt text. The homepage hero calls the same pipe with wider `widths` (see `.widths`/`.fallbackWidth` below). This partial deliberately does not consult showimage — it answers "what derivatives exist", not "should this page show a photo". Callers gate on show-image.html first, exactly as they did for the single original. Raster only, on purpose. The eight section bundles also carry artwork matching the same `photoGlob`, but it is SVG at ~2 KB each — resolution independent, so there is nothing to resize and rasterising it would make it both larger and blurrier. Returning nothing for a vector leaves the caller on its plain original, which is what section-card.html wants. The guard is here so that "use dish-image for the section art too" is not a tempting but wrong refactor. Returns nothing when the page bundle holds no raster photo matching the glob, so callers can wrap it in `with`. */ -}} {{- /* `.src` lets a caller that already holds the resource — the homepage hero, which matches images/photo-*-hero.* rather than a page bundle — skip the resolution below and still share the one processing path. `.widths`/`.fallbackWidth` widen the ladder for a slot that spans the full viewport instead of a 357px card. Read before `with $src` rebinds `.` to the resource: inside that block `.widths` would be a lookup on an image resource, which has no such field. */ -}} {{- $src := default "" .src -}} {{- $widths := .widths | default (slice 480 768 1080) -}} {{- $fallbackWidth := .fallbackWidth | default 1080 -}} {{- if not $src -}} {{- $page := .page -}} {{- $glob := $page.Site.Params.photoGlob | default "photo-*-hero.*" -}} {{- /* Only the page's own bundle is consulted, so a page can resolve nothing but its own file — there is no global glob that could hand all 46 dishes the same first match. The eight section bundles carry artwork under the same photoGlob but it is SVG, and this partial is raster-only (see above), so the vector is skipped here rather than rasterised. */ -}} {{- with $page.Resources.GetMatch $glob -}} {{- if ne .MediaType.SubType "svg" -}} {{- $src = . -}} {{- end -}} {{- end -}} {{- end -}} {{- with $src -}} {{- $src := . -}} {{- /* Never resize past the source. Hugo's resize upscales, which adds only blur and bytes, and both the width/height and the JSON-LD image are read off the largest step, so an over-wide step would also misstate the real dimensions. Capping here means a caller can keep one generous ladder — the 100vw hero asks for up to 1200 — and a 1080px source silently drops just the 1200 step, no matter which template calls in. If every step exceeds the source, fall back to the source width so the set is never empty. */ -}} {{- $ladder := slice -}} {{- range $widths -}} {{- if le . $src.Width -}}{{- $ladder = $ladder | append . -}}{{- end -}} {{- end -}} {{- if not $ladder -}}{{- $ladder = slice $src.Width -}}{{- end -}} {{- $webpSet := slice -}} {{- $width := 0 -}} {{- $height := 0 -}} {{- $largest := "" -}} {{- range $ladder -}} {{- $r := $src.Process (printf "resize %dx webp q82" .) -}} {{- /* `fingerprint` as a function, not `.Fingerprint` as a method: on images.ImageResource in Hugo 0.167 the method form is not exposed and `{{ .Fingerprint }}` fails to parse. Same output either way, and the hash is the point — without it a re-encoded photo keeps its URL and a cached copy never gets replaced, which is the same staleness rule AGENTS.md states for the stylesheet. */ -}} {{- $r = $r | fingerprint "sha256" -}} {{- $webpSet = $webpSet | append (printf "%s %dw" $r.RelPermalink $r.Width) -}} {{- $width = $r.Width -}} {{- $height = $r.Height -}} {{- $largest = $r -}} {{- end -}} {{- $fallback := $src.Process (printf "resize %dx jpg q82" (int (math.Min $fallbackWidth $src.Width))) -}} {{- $fallback = $fallback | fingerprint "sha256" -}} {{- return dict "webp" (delimit $webpSet ", ") "fallback" $fallback.RelPermalink "width" $width "height" $height "permalink" $largest.Permalink -}} {{- end -}}
